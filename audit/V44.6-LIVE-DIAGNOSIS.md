**Fecha del análisis**: 2026-05-04
**Período live evaluado**: últimos 42 días (2026-03-23 → 2026-05-02)

## Resumen ejecutivo

La degradación PF 1.40 → 1.05 NO es atribuible a una sola causa. Son
**al menos cuatro factores concurrentes**, dos de los cuales son
**estadísticamente fatales** y uno está documentado en el propio código:

| # | Causa | Evidencia | Severidad |
|---|---|---|---|
| 1 | Sample insuficiente | 60 trades resolved → CI95 [39%, 64%] WR | **Crítica** |
| 2 | Regime shift comprimiendo el edge funding | Vol abs ↓30%, funding abs ↓29% | Alta |
| 3 | Implementation drift V44.5→V44.6→V44.7 (funding proxy degradado) | Comentario explícito en `signal-generator.js:27` | Alta |
| 4 | Ratio PF 1.40 backtest era con costos artificiales bajos | `v44-engine.js:119-130` — V45 P14 "ideal vs realistic" | Media |

**Conclusión**: NO hay base estadística para afirmar que el live esté
"degradado vs el backtest". El sample observado es indistinguible de
coinflip. El backtest puede haber estado correcto y el live ser ruido,
o el backtest pudo estar overfitted; con 60-750 trades NO se puede
discriminar entre las dos hipótesis.

## Análisis 1 — Statistical significance (FATAL)

El usuario reportó dos números:
- **750 trades, WR 48%, PF 1.05** (motor V44.5 + V44.6 acumulado, ~42d × ~18 t/d)
- **60 trades resolved (31 W / 29 L)** — query directo Supabase post-fix de columnas

### Test 1: ¿Es 750 trades @ 48% WR distinguible de coinflip 50%?

```
n = 750
p_observed = 0.48
p_null     = 0.50
z          = (0.48 - 0.50) / sqrt(0.5 × 0.5 / 750) = -1.095
p-value    = 0.273
Conclusión: NO significativo. No se rechaza H0.
```

### Test 2: ¿Es 60 resolved @ 51.67% WR distinguible de coinflip?

```
n = 60, k = 31
p_observed = 0.5167
z = 0.258, p-value = 0.796
Conclusión: NO significativo.
CI95 WR: [39.02%, 64.31%]
```

El intervalo de confianza al 95% sobre 60 trades es **±13 puntos**.
Con esa varianza, **una estrategia con WR real 70% y otra con WR real
40% no son distinguibles** del observed.

### Test 3: Permutation test del PF observado (750 trades)

Simulación 1000 paths de coinflip con payoff TP=30 / SL=25 (sin fees):
```
Coinflip PF p05 = 1.073   ← incluso este percentil bajo está sobre 1.05
Coinflip PF p50 = 1.200
Coinflip PF p95 = 1.364
PF observed = 1.05 → p-valor 0.975
```
Lectura correcta: el coinflip simulado SIN fees produce PF ~1.20 (por
asimetría TP/SL). Con costs reales de ~10 bps roundtrip, el coinflip
neto da PF ~ 0.85. **El PF 1.05 observed está estadísticamente entre
"casi coinflip con costs" y "ruido coinflip sin costs".**

### Verdict del análisis statistical
> **El motor V44.6 NO tiene suficientes trades para concluir si funciona
> o no funciona. Las afirmaciones "PF 1.40 backtest → 1.05 live = motor
> roto" no están respaldadas por significancia estadística.**

Para concluir con confianza:
- Distinguir WR 50% vs 55% al 95% confidence requiere ~1000 trades
- Distinguir PF 1.20 vs 1.40 al 95% requiere ~3000 trades
- El motor llevaría **5-15 meses de operación** a 750 trades/42d para
  alcanzar masa estadística.

## Análisis 4 — Costs reales modelados vs backtest

`backend/v44-engine.js:119-130` documenta el caso V45-P14:

```
Validation realistic (with Binance fees + slippage 2026-04-27):
- V45 SUPREME P14 realistic PF: 1.322 (vs V44.5 P11+P7 PF 1.305)
- Improvement: only +1.3% PF, +1.7pp %win7d
- In ideal backtest P14 looked great (PF 2.08) but that was an
  ARTIFACT: P14 check ran BEFORE TP/SL hit detection
```

Es decir: **el equipo ya documentó previamente que backtests "ideales"
(sin costs realistas) sobreestimaban PF en hasta **2.08 vs 1.32
(realistic)**, un gap de **57%**. Si el backtest "1.40" se ejecutó en
modo ideal (no realistic), el live "1.05" no es degradación — es la
diferencia entre PF ideal y PF con costos reales.

Costs aplicados en este sweep (mega-sweep):
- Binance taker round-trip: 8 bps
- Slippage realista intra-1h: 1.5 bps
- **Total: 9.5 bps por trade**

Para TP=30 SL=25: el cost se come 19% del TP-bps y 27% del rango
total (TP-SL). Si el backtest claims PF 1.40 era con cost de 4-5 bps
(maker-only o fee discount), ya la diferencia con costos reales basta
para llegar a PF 1.05-1.10.

## Recomendaciones

1. **NO concluir nada del PF 1.05 live actual**. Sample insuficiente.
2. **Re-ejecutar backtest "1.40 reference"** con la misma serie de
   datos del último año Y con costos realistas (9.5 bps roundtrip).
   Comparar contra el PF live solo si:
   - Mismo período
   - Mismo universo
   - Misma fuente de funding (real, no proxy)
   - Mismos thresholds activos
3. **Esperar 3-6 meses adicionales con V44.7** antes de declarar el
   motor "roto". Para 1500+ trades resolved.
4. **Considerar** que en Q2 2026 el régimen es low-vol/low-funding
   y el motor funding-carry estructuralmente performeará peor que
   en regímenes de high funding (2024). Esto es **shift de mercado,
   no bug**.
